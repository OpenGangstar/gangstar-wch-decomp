## Separate return-declaration control

The original SDK declares `void set(float,float,float)`; the partial header
declares a quaternion reference return. The examined native callers discard
R0 and pass preserved object addresses. That is compatible with void, but does
not prove the fork's declared return type or cover every retail caller.

Pinned GCC 4.2.1 `calls.c` initially chooses a call-value versus call RTL form
from the declared result type before discarding an ignored expression value.
Therefore final code identity cannot simply be assumed. One separately approved
control changes only that declaration in the original 4336-byte fixture; every
Vehicle.cpp byte remains unchanged. It does not compose either conditional form.

The result stays 4336 bytes. Exactly four target bytes at offsets 0xaf4 through
0xaf7 change: two pre-constructor home-pointer moves exchange order. Frame,
homes, duplicated calls, literal positions and relocation counts stay unchanged.
It supplies no native-extent improvement, header adoption or match credit.
No additional return-type or constructor variant is justified by this result.
